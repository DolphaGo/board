## 요구사항과 완료 조건

PR을 열면 외부 레지스트리 자격 증명 없이 코드의 테스트와 빌드를 확인한다. 검증을 통과한 `develop` 푸시에서만 기존 두 애플리케이션 이미지를 GHCR에 게시한다.

- 백엔드 테스트와 실행 가능한 JAR 빌드가 성공한다.
- 프런트 테스트, TypeScript 검사, Vite 빌드와 프런트 API JAR 빌드가 성공한다.
- PR에서는 Jib 게시 작업을 실행하지 않는다.
- 기존 게시 대상 이미지 이름과 배포용 환경 변수, secret 참조를 유지한다.
- 최신 JDK를 사용하는 백엔드 변경과 맞춰 컨테이너의 Java 실행 버전도 확인한다.

## CI와 CD

CI(Continuous Integration)는 변경을 합치기 전에 테스트와 빌드로 문제를 발견하는 과정이다. PR의 검증 결과는 해당 코드가 현재 검증 항목을 통과했는지 보여 준다.

CD는 검증된 결과를 배포 가능한 형태로 전달하는 Continuous Delivery 또는 실행 환경까지 자동 반영하는 Continuous Deployment를 가리킨다. 이 저장소의 워크플로가 수행하는 전달 단계는 Jib으로 컨테이너 이미지를 만들어 GHCR에 올리는 것까지다. 이미지를 게시했다고 실행 서버의 새 버전 반영이나 정상 응답까지 확인한 것은 아니다.

PR은 아직 합쳐지지 않은 변경이다. PR마다 같은 `latest` 태그를 게시하면 검토 중인 코드가 기존 배포용 이미지 태그를 덮을 수 있다. 또한 코드 검증의 성공 여부가 레지스트리 토큰의 권한에 의존하게 된다. 따라서 PR 검증과 이미지 게시의 실행 조건을 분리한다.

## 실패 근거와 수정

[기존 PR 실행](https://github.com/DolphaGo/board/actions/runs/37038377146)에서 다음 두 실패를 확인했다.

1. 프런트 작업의 `installFrontendDependencies`에서 `A problem occurred starting process 'command 'pnpm''`이 발생했다. 기존 워크플로는 JDK만 준비했지만 Gradle의 프런트 빌드는 외부 `pnpm` 명령을 실행한다. 프런트를 빌드하는 검증 job과 게시 matrix 항목 모두에 pnpm과 Node 설정을 추가했다.
2. 백엔드 Jib 작업은 `ghcr.io/dolphago/board-api`의 게시 권한 또는 자격 증명 오류를 보고했다. 같은 로그에서 베이스 이미지 digest를 받은 사실을 확인했으므로 베이스 이미지 태그 오류로 판단하지 않았다. PR은 이제 레지스트리 게시를 실행하지 않으며, `develop` 게시용 secret의 실제 유효성은 별도로 확인해야 한다.

별도의 최신 버전 요구에 따라 Java 21 베이스 이미지도 Java 27 이미지로 바꾼다. `eclipse-temurin:27-jre`는 확인 시점에 manifest가 HTTP 404였으므로 사용하지 않았다. 대신 [AWS 공식 Java 27 Docker 문서](https://docs.aws.amazon.com/corretto/latest/corretto-27-ug/docker-install.html)와 [Docker 공식 이미지 태그 목록](https://github.com/docker-library/official-images/blob/master/library/amazoncorretto)에 등록된 `amazoncorretto:27.0.0-al2023-headless`를 선택했다. 공개 manifest는 HTTP 200이며 Linux amd64·arm64를 포함한다. 이 이미지는 선행 백엔드 변경의 표준 Jib `mainClass` 진입점과 함께 사용해야 한다. 기존 사용자 이미지의 `INHERIT` 진입점을 그대로 적용하지 않는다.

## 검증 단계와 의존 관계

| Job | 실행 조건 | 확인 내용 |
| --- | --- | --- |
| `backend` | PR 또는 `develop` 푸시 | `:board-api:test`, `:board-api:bootJar` |
| `frontend` | PR 또는 `develop` 푸시 | 잠금 파일 설치, `pnpm test`, `pnpm lint`, `:board-front:board-front-api:bootJar` |
| `build` | 두 검증 성공 후 `develop` 푸시 | 기존 두 모듈의 Jib 이미지 게시 |

프런트 API의 `bootJar`는 `processResources → buildFrontend` 순서로 UI 빌드를 요구한다. `buildFrontend`가 `pnpm run build`를 실행하므로 TypeScript 7 native, Vue 타입 검사, Vite 빌드와 UI 정적 파일의 JAR 포함까지 함께 확인한다. 프런트 테스트와 lint는 그 전에 별도 단계로 실행한다. `pnpm test`는 최신화 변경의 `vitest run` 스크립트를 호출하며 개발용 감시 모드로 남지 않는다.

`needs: [backend, frontend]`는 이미지 게시가 두 검증의 성공을 기다리게 한다. 게시 job의 `if`는 이벤트가 `push`이고 브랜치가 `refs/heads/develop`일 때만 참이므로 PR에서는 건너뛴다.

`--frozen-lockfile`은 설치 과정에서 잠금 파일을 임의로 갱신하지 않게 한다. Node의 pnpm 캐시를 사용하기 전에 pnpm 실행 파일이 필요하므로 `pnpm/action-setup`을 `actions/setup-node`보다 먼저 둔다.

## 검증과 한계

2026-10-03 로컬 검증 결과:

| 검증 | 결과 |
| --- | --- |
| `pnpm install --frozen-lockfile` | Node 26.10.0·pnpm 12.8.1에서 성공, 잠금 파일 변경 없음 |
| `pnpm exec jest --runInBand` | 같은 Node·pnpm에서 28개 suite, 247개 테스트 통과 |
| `./gradlew :board-api:test :board-api:bootJar` | Java 21과 Java 27에서 각각 성공, 91개 테스트 실패 없음 |
| `./gradlew :board-front:board-front-api:bootJar --rerun-tasks` | Java 21·최신 Node·pnpm으로 타입 검사, Vite 빌드, 프런트 API JAR 생성 성공 |
| `actionlint` 1.7.12, `git diff --check` | 오류 없음 |

Gradle 검증 명령에는 로컬 동시 작업의 리소스 사용을 줄이기 위해 `--no-daemon --max-workers=2`를 추가했다. Java 27은 Temurin 공식 배포 파일의 SHA-256을 검증한 뒤 임시 경로에 설치해 사용했다.

위 테스트는 변경 전 애플리케이션(Gradle 9.5.1, JVM 대상 21, Jest)의 기준선이다. 이후 최신 백엔드·프런트·글쓰기 변경을 이 브랜치에 연결하고 아래 통합 검증을 수행했다. 이 워크플로는 해당 선행 변경과 함께 검토한다.

로컬에서는 Jib의 원격 이미지 게시를 실행하지 않았다. GHCR secret 권한과 새 이미지로 운영 서버를 시작한 결과는 별도 운영 확인 범위다. PR 검증 완료가 운영 배포 완료를 뜻하지 않는다.


### 최신 환경 통합 검증

마무리 시점에 공식 레지스트리를 다시 조회했다. 42개 프런트 직접 의존성 중 ESLint만 10.11.0에서 새 안정판 10.12.0으로 갱신이 필요했다. Node 26.10.0, Gradle 9.8.0과 조회한 백엔드 안정 버전 13개는 유지됐다.

ESLint와 잠금 파일을 함께 갱신했다. ESLint 10.12.0은 2026-10-02 20:08:19 UTC에 게시돼 pnpm의 기본 24시간 출시 대기 범위 안에 있었다. 명시적인 최신 버전 설치가 생성한 정확한 버전 예외 `eslint@10.12.0`을 기록했고, 나머지 공급망 검사를 끄지 않았다. 최신 버전 선택과 잠금 파일 고정, 설치 정책의 역할을 구분한다.

| 검증 | 실제 결과 |
| --- | --- |
| Node 26.10.0·pnpm 12.8.1 frozen install | 통과, 설치 시 잠금 파일 추가 변경 없음 |
| `pnpm test` | 28개 파일, 275개 통과 |
| ESLint 10.12.0의 `pnpm lint` | 오류 0, 스타일 경고 494 |
| JDK 27의 전체 Gradle 검증 및 두 bootJar | 통과. API 102개와 프론트 API 1개 테스트, 실패·오류·skip 0 |
| 이 CI 브랜치의 프론트 API bootJar | 통과. 최신 TypeScript native·Vue 검사·Vite·Kotlin 패키징 확인 |

[글쓰기 PR #16](https://github.com/DolphaGo/board/pull/16)에서 `vi.*`로 수정하고 실제 저장·재조회까지 검증한 변경을 연결했다. 새 러너 결과는 이 PR의 Checks와 [후속 이슈 #15](https://github.com/DolphaGo/board/issues/15)에 남긴다.
