## 요구사항과 완료 조건

목록에서 고른 글을 읽고 같은 목록 페이지로 돌아간다. 없는 글과 서버 오류를 구분하며, 글 사이를 빠르게 이동해도 이전 본문·댓글·추천 상태가 새 글에 섞이지 않아야 한다.

- 양의 정수 ID만 조회하고, 존재하지 않는 글은 HTTP 404와 안내를 표시한다.
- 실패·숨김·정상 상태에서 목록 이동이 가능하고 전달받은 `page`를 보존한다.
- 이전 상세·관련 글·액션 응답은 현재 글을 덮어쓰지 않는다.
- 검색 서버의 관련 글 응답이 늦어도 본문·댓글 읽기는 시작할 수 있다.
- 경로 변경 시 작성 중 댓글과 이전 글의 추천 완료 상태를 초기화한다.

## 구현 순서

1. 경로 변경·응답 역전·404·관련 글 지연에 대한 실패 테스트를 추가한다.
2. 로딩 상태와 부가 요청을 분리하고 현재 조회에 해당하는 응답만 반영한다.
3. 서버의 없는 글 예외를 명시적인 404 계약으로 연결한다.
4. HTTP/H2, 프론트 테스트, 실제 브라우저에서 검증하고 결과를 채운다.

## 개념과 코드 읽기

**자원과 HTTP 상태**: URL의 글 ID는 저장된 자원을 식별한다. 존재하지 않는 글은 서버 장애(500)와 구분한 404를 반환한다. [PostService](../../board-api/src/main/kotlin/dev/dolphago/service/PostService.kt)의 `PostNotFoundException`을 [PostController](../../board-api/src/main/kotlin/dev/dolphago/controller/PostController.kt)의 예외 처리기가 HTTP 계약으로 바꾼다. 화면은 상태 코드를 보고 ‘없는 글’과 ‘재시도 가능한 조회 실패’를 구분한다.

**컴포넌트 재사용과 상태 범위**: 라우터는 같은 상세 컴포넌트에서 ID만 바꿀 수 있다. [PostDetail.vue](../../board-front/board-front-ui/src/components/PostDetail.vue)는 ID를 감시하고 본문·댓글 초안·추천 완료·액션 메시지를 새 조회마다 초기화한다. 화면의 값은 컴포넌트 수명 전체가 아니라 현재 글에 속한다.

**응답 순서와 부가 요청**: 조회 번호를 함께 보관해 이전 본문·관련 글·추천/댓글/숨김 응답을 버린다. 같은 ID로 다시 돌아와도 번호가 달라 이전 응답을 구별한다. 관련 글은 본문 뒤의 부가 정보라 `await`로 전체 로딩을 붙잡지 않는다. 서버 요청 자체를 취소하는 방식은 아니며, 이미 실행된 쓰기 작업은 서버에서 완료될 수 있다.

**복귀 경로**: 목록 링크를 성공한 본문 밖에 둬 오류에서도 사용할 수 있게 한다. 목록에서 받은 `page`를 양의 정수로 확인해 목록 URL에 넣는다. 관련 글은 일반 `<a>` 대신 RouterLink로 이동해 hash router의 경로를 유지한다.

테스트를 읽는 순서: [PostDetail.spec.ts](../../board-front/board-front-ui/src/components/PostDetail.spec.ts) → [PostDetailApiIntegrationTest](../../board-api/src/test/kotlin/dev/dolphago/controller/PostDetailApiIntegrationTest.kt). 프론트 테스트의 지연된 Promise는 응답 순서를 통제하고, HTTP 테스트는 실제 H2 데이터와 404 매핑을 확인한다.

## 검증

| 방법 | 결과 |
| --- | --- |
| 기존 구현에 경로 변경·404·관련 글 지연 테스트 추가 | 새 프론트 테스트 9개 실패 재현 |
| 수정 후 프론트 전체 `jest --runInBand` | 28개 파일, 266개 통과 |
| `vue-tsc --noEmit`, `vite build` | 통과 |
| `JAVA_HOME=<JDK21> ./gradlew :board-api:test --no-daemon --max-workers=2` | 97개 통과. 실제 HTTP에서 본문·작성자·조회수 1→2, 없는 ID 404 확인 |
| 실제 API + 390×844 브라우저 | 목록 2페이지 → 상세 → 목록 2페이지 복귀. 없는 글에서도 같은 목록 링크 제공 |
| 실제 API + 1440×1000 브라우저 | 긴 제목 가로 넘침 없음 |
| 브라우저 제어 응답 | 상세 500 주입 후 재시도, 주입 해제 후 실제 본문 조회 성공 |

검색 서버 없이 실행해도 본문은 표시된다. 관련 글 조회 실패는 검색 기능의 미검증 범위로 남긴다. 최신 도구 전체 이행은 별도 버전 PR에서 재검증한다.

## 실패와 해결

첫 404 수정에서는 예외 클래스와 처리기를 만들었지만 실제 `orElseThrow`가 여전히 일반 예외를 생성했다. 실제 HTTP 테스트가 500을 잡았고 별도 코드 리뷰도 같은 연결 누락을 지적했다. 조회 경로가 `PostNotFoundException`을 생성하도록 고친 뒤 전체 서버 테스트와 실제 404 응답을 확인했다.
